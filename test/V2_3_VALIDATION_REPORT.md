# V2.3 通用知识 Agent 验证报告

## 验证目标

本报告验证两件彼此独立的事情：

1. `data-v2.3` 是否不依赖 API 原生 tool/function calling，只要模型接口能返回普通文本就可以工作；
2. SC2 数据是否在正确的决策时机改变可执行队列，而不是只增加 prompt、延迟和看似合理的解释。

所有正式长局统一使用：`DeepSeek-V4-flash`、non-thinking、
`KairosJunctionLE`、Hard、Macro 对手、60 秒决策间隔、游戏内时间上限
`1200s`（20:00）。三个我方种族各选一个复杂策略，并分别面对另外两个
种族，共 6 个 matchup。

## API 通用性

V2.3 的 MainAgent 与 DataSubAgent 都只发送普通文本 chat completion。仓库本地
`PortableKnowledgeRouter` 负责选择和执行查询函数，API 请求不包含 `tools`、
`tool_choice`、tool message 或 function call。MediumHard 的六局接入 smoke 中，
99 次模型请求全部记录为 `portable_text_v1`，无工具、trace 或决策错误。

## 第一轮 20 分钟诊断

冻结批次：

- V2.3 knowledge：`v23_ds4f_hard_20m_6_20260805_r4`
- V2 harness no-external-knowledge：`v2noknow_ds4f_hard_20m_6_20260805_r2`
- naive：`naive_ds4f_hard_20m_6_20260805`

| Agent | 胜 | 平 | 负 | 平均 RUR | 平均资源浮存 | 平均 APU |
|---|---:|---:|---:|---:|---:|---:|
| V2.3 knowledge（组合修正前） | 0 | 3 | 3 | 1089.4 | 3335.8 | 0.618 |
| V2 harness no-external-knowledge | 1 | 3 | 2 | 1160.9 | 2763.9 | 0.618 |
| naive | 0 | 0 | 6 | 813.7 | 2226.9 | 0.516 |

V2.3 完成 137 次常规决策、17 次真实知识查询、66 次本地工具请求与 66 次
响应；183 次模型请求全部使用 `portable_text_v1`。两次 trace 失败来自最终队列
无法通过确定性验证，不是 API 或工具协议错误。

这轮结果不能支持“knowledge 已产生胜率增益”。相反，它暴露了知识利用边界：

- 17 次查询中只有 2 个时刻真正改变队列，检索大多停留在解释层；
- `combat_capability` 偏好能同时攻击全部目标层的通用兵种，弱化了“对地克制 +
  防空”的组合；
- 多次查询发生在我方战力已经归零之后，事实虽然正确但没有兑现窗口；
- LLM 会把“能攻击”误写成“克制”，甚至在公开解释里声称 Viking fighter
  能对地，说明模型自身知识仍会污染仓库证据；
- 高矿高气时，昂贵同类单位排在队首会形成气体前缀瓶颈，后面的矿物兵种无法
  及时转化为战力；
- Hard 对手的交战结果具有随机性，6 局只能用于功能与方向判断，不能形成稳定
  胜率结论。

## 针对 LLM 缺点的第二轮修正

V2.3 随后增加了知识组合与时机约束：

- 分开输出 `preferred_mobile_by_layer.air` 与 `.ground`；
- 每个真实攻击层缺口前置一个已验证、当前可生产的移动单位；
- 降低“一个单位覆盖全部目标”的排序奖励，允许专职防空和对地克制组成组合；
- 当敌军战力至少为 8，且我方不超过敌方 125% 时，提前查询 composition
  counter，而不是等待直接攻击层归零；
- 仍保留资源、供给、生产者、前置科技和执行容量的确定性审计；查询失败仍可
  降级为不带知识的生存决策。

|---|---:|---:|---:|---:|---:|---:|
| V2.3 组合知识 | 1 | 3 | 2 | 1392.9 | 3400.6 | 0.632 |

| naive | 0 | 0 | 6 | 813.7 | 2226.9 | 0.516 |

组合修正相对修正前由 `0/3/3` 改善为 `1/3/2`。相对无外部知识组，六局胜平负
相同，但平均 RUR 提高约 20%，APU 提高 0.014；PvZ 多生存 5:57，ZvP 从平局
变为胜利。另一方面，TvZ 从胜利变为平局，平均资源浮存高约 23%。因此当前证据
支持“知识更早、更实际地参与了战力转换”，但不支持声称六局胜率已经显著超过
无知识 harness。

V2.3 组合知识组包含 175 次常规决策、40 个使用知识的决策、33 个缓存命中、
96 次本地工具请求与 96 次响应。251 次模型请求全部为 `portable_text_v1`；没有
API tool/function-call 兼容性错误。知识层产生 7 次已验证单位前置、1 次插入以及
156 次可执行战力填充，说明证据不再只停留在解释文本。

该批次有 4 个 trace 在基地、工人或关键科技已被摧毁的末局 recovery 状态中，
因为不可能在当前 horizon 精确满足防空/对地标量目标而耗尽修复轮次。赛后已将
这种情况改为：保留经过预算、前置和 canonical 审计的 best-effort 恢复队列，
同时记录未满足的 response target，不再丢弃整次决策。完整测试为 145 passed。

所有中断、启动失败或较短的 600 秒批次只作为诊断，不计入正式胜率表。六局结果
对随机性很敏感；若要证明统计增益，应冻结本版本后按 matchup 多 seed 配对扩样。
